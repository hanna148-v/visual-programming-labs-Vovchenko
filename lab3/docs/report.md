**Что посмотрела.** Гайд из четырёх шагов: подготовка базы данных, дизайн страницы с текстовым элементом и Repeating Group, workflow для обновления счётчика, тестирование в Preview.

**Что взяла в приложение.** Счётчик «Всего книг: N». Реализовала проще, чем в гайде. Гайд хранит число в поле пользователя и увеличивает его в workflow при каждом добавлении книги. Но в моём приложении нет регистрации, а число можно получить прямо из базы. Поэтому в текстовом элементе использовано динамическое выражение `Do a search for Books:count` без ограничений. ![Страница notes в редакторе](../screenshots/09-notes-design.png)

Workflows настроены вручную, каждое действие отдельным workflow:

| Операция | Элемент | Что происходит |
|---|---|---|
| **Create** | кнопка «Добавить заметку» | Create a new thing: тип `ReadingNote`, поля берутся из элементов формы |
| **Read** | Repeating Group «Все заметки» | источник данных `Do a search for ReadingNotes`; workflow не нужен, список обновляется сам |
| **Update** | кнопка «Редактировать» | Make changes to a thing: изменяется запись выбранной ячейки |
| **Delete** | кнопка «Удалить» (`Button Delete`) | workflow «Ask delete note»: действие Display data передаёт заметку (`Parent group's ReadingNote`) в `Popup Confirm Delete`, затем действие Show открывает окно; после подтверждения запись удаляется |

## 6. Какие элементы и workflows освоены

**Элементы Design:** Text, Input, Multiline Input, Dropdown, Date picker, Checkbox, Button, Repeating Group (ячейка `Cell`, источник данных), Popup, ссылка на другую страницу, готовый компонент из COMPONENTS.

**Global:** цветовая переменная, переиспользуемый стиль элемента.

**Data:** Data types и их поля (текст, число, дата, yes/no, связь с другим типом), App data, ручное добавление записей, динамические выражения `Do a search for … :count`.

**Workflows:** Create a new thing, Make changes to a thing, Delete a thing, Display data in popup, Show popup. Привязка workflow к клику по кнопке.

> TODO: переписать своими словами. Ниже черновик, основанный на реальном ходе работы.

AI-агент быстро собрал рабочий каркас: тип данных, страницу, форму и список. Но результат пришлось проверять и дорабатывать вручную. Например, при ручных правках я несколько раз помещала элементы внутрь ячейки Repeating Group, из-за чего они повторялись для каждой записи. Так я на практике разобралась, чем отличаются сам Repeating Group, его ячейка и остальная страница.

Build Guide дал идею, но решение пришлось адаптировать: счётчик из гайда был рассчитан на приложение с пользователями, а для публичного каталога достаточно поиска с `:count`.

Глобальная переменная и стиль помогают менять внешний вид в одном месте, а не на каждой кнопке. Тип данных в Bubble аналогичен таблице базы данных, а workflows связывают действие пользователя (клик) с изменением данных.

Из недостатков: на формах нет проверки значений, поэтому можно сохранить оценку больше 5 или нереальную дату. В дальнейшем это стоит исправить условиями в workflow. Кроме того, светло-жёлтые кнопки с белым текстом плохо читаются, цвет стоит подобрать иначе.
